# Version: *1.2.0* - Date: *2025-08-23*

---

### 🚀 **Overview**
Version 1.2.0 is now released. This update brings major improvements in provider handling, OpenIdConnect flows, settings generation, and internal service refactoring, along with numerous bug fixes and performance enhancements.

### ✨ **Added**
* ProviderRegistrySqlModel and supporting logic for tracking running services, heartbeat monitoring, and main provider assignments.
* M2M token generation support for OpenIdConnect.
* Public key token generation (JWKS) support.
* Visualization of provider URL in the UI.

### 🔄 **Changed**
* Refactored routes, claims, and project structure.
* Enhanced user-related methods and user schema.
* Internal services renamed for clarity.
* Enhanced settings generation logic.
* OpenIdConnect flow refactored for proper functionality.
* Authorize property renamed to RequiresAuthentication for clarity.
* DataValidationService refactored for improved performance.
* LicenseService and Basic Auth Handler refactored.
* Updated token handling for OpenIdConnect.
* Added custom data protection for provider cookie communication.

### 🐛 **Fixed**
* Bug where class name count calculation was incorrect.
* Bug where SPA document title was not properly input type.
* OpenIdConnect not working due to incorrect NuGet package version.

> [!IMPORTANT]
> **Database migrations** are required for upgrading to version 1.2.0. If your application is running as a **provider**, ensure that you apply the necessary migrations to support the new configuration settings being stored in the database.  
>  
> To apply the migration, run the following command:  
>  
> `dotnet ef migrations add OpenSettingsDbMigration_v1_2 -c OpenSettingsDbContext -o Data/Migrations/OpenSettings/OpenSettingsDb`  
>  
> For more details, check the [Upgrading Page](../upgrading/v1.1-to-v1.2.md).
